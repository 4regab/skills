# Overused App Ideas

Some shapes are so copied that building another one is almost never a product. It can still be practice. This skill names the grave and raises the bar.

Run this first, before `find-existing-apps`. It is a heat check, not a substitute for search.

## How to use

1. Match the idea against `references/graveyard.md`.
2. If it hits, say the category name out loud and the usual failure.
3. Ask which exception they think they have. Most exceptions are fake — see `why-this-is-different`.
4. Continue to `find-existing-apps` even if they insist. The scan must list the twenty existing copies.

Do not shame the maker. Name the category and the usual failure, then keep moving. This is not a ban list.

## Heat levels

- **Hot grave** — daily on SideProject / SaaS. Default verdict is USE or EXTEND. Building requires a brutal wedge plus named users.
- **Warm grave** — crowded but a narrow scene can still live. Scan hard. Demand a scene, not a persona.
- **Learning-only** — fine as a tutorial. Label the repo as a clone. Do not write launch copy.

## Agent behavior on a hit

First reply must include

- Category and heat
- Why this shape dies (one sentence, from the graveyard file)
- Three named incumbents you already know, plus "scan will find more"
- The path they still have: use one, fork one, or state a wedge for a named scene

Then run `find-existing-apps`. Do not skip it because the category is obvious.

## Strong recommend

If they want the 40th todo list as practice, build a tiny one. No auth platform, no AI layer, no PH launch kit.

If they want it as a business, do not help them pretend it is original. Help them find the scene or walk away.

## What this skill is not

It is not a ban list for all time. A habit tracker for oncology nurses on night shift is a different product than "HabitKit but mine." The graveyard flags the generic form. The wedge decides whether the specific form survives.
