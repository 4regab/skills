# Fake wedges

Reject these as the "because" clause. They describe taste, stack, or marketing — not a constraint.

## Category theater

- AI-powered X
- ChatGPT for {industry}
- agentic / autonomous / copilot for X
- Uber for X, Airbnb for X
- OS / platform / hub for X
- all-in-one workspace

## Surface theater

- minimalist
- beautiful UI
- mobile-first (when the job is not mobile)
- dark mode, animations, "delight"
- built with Next.js, Supabase, serverless scale

## Audience theater

- for founders
- for busy professionals
- for Gen Z
- for everyone who wants to be productive

## Roadmap theater

- we will add integrations later
- marketplace later
- social layer later
- the moat is execution speed

## How to push back

Ask one question: "If `{incumbent}` shipped your twist on Friday, would your user switch?"

- If yes, there is no wedge. USE or EXTEND.
- If no, the reason they would not switch is the real constraint. Put that in the sentence.
