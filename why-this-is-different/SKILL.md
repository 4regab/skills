# Why This Is Different

A clone with nicer type is still a clone. This skill turns "but mine is different" into a sentence a stranger could falsify.

Run after `find-existing-apps`. If the scan was skipped, run it first.

## The wedge sentence

The user must fill this, in their words, not yours:

> For `{specific person in a specific situation}` who already `{current workaround}`, this does `{one job}` that `{named incumbent}` will not do because `{constraint the incumbent ignores}`.

Rules

- Person is a role plus context, not "users" or "everyone."
- Workaround is what they do this week (spreadsheet, WhatsApp, memory, a named app).
- Job is one verb phrase.
- Incumbent is a real name from the scan.
- Constraint is structural (workflow, regulation, language, offline, price, distribution, data they already have) — not "better UX" or "AI."

If they cannot fill it, they do not have a wedge. Say that. Then offer USE or EXTEND again.

## Fake wedges (reject these)

Do not accept any of the following as the constraint

- AI-powered, GPT, agents, smarter
- cleaner UI, modern, minimal, dark mode
- faster to build because of Cursor / Copilot
- all-in-one, platform, operating system for X
- for everyone, for founders, for productivity people
- we will add more features later
- mobile and web
- "no one has done it exactly like this"

See `references/fake-wedges.md`.

## Honest wedges (accept these)

A constraint is honest when an incumbent would have to hurt their current business to copy it.

Examples of shape, not ideas to copy

- Works inside a tool the user cannot leave (a specific EHR, a school's SIS, a broker's terminal)
- Speaks a language / regulation / union rule the category leader ignores
- Uses data the user already captured that the leader cannot access
- Offline, air-gapped, or no-account on purpose
- Priced for a buyer the leader priced out (or the reverse)
- Built for a workflow that is ugly on purpose (shift handover, farm radio, cash-only stall)

Lived experience counts. "I am that user every day" is a starting constraint. It still needs the sentence.

Also accept a real gain in accessibility, local language, offline use, integrations, cost, simplicity, reliability, or workflow fit. Do not require a globally new category. A reskin or vague AI claim is still fake.

## Output

Print the filled sentence. Then three bullets

- Why this is not `{top incumbent}`
- What we will refuse to build (features the incumbent already owns)
- What `proof-of-demand` must confirm before more surface area

If the sentence is weak, do not rewrite it into something impressive. Show the hole and ask them to patch one slot.

## Strong recommend

Tone and timing come from the one hard round in `look-before-building`. Push back once, hard, then build.

If they insist on building with a weak wedge, build the smallest proof of that sentence only. Do not scaffold the full suite. Name the clone risk in the README.
